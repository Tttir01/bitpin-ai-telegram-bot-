# MVP مستقل آربیتراژ والکس / نوبیتکس

این پوشه یک مسیر اجرای مستقل برای نمونه‌سازی است؛ فعلاً فقط داده عمومی را می‌خواند، محاسبه paper انجام می‌دهد و تاریخچه را در SQLite ذخیره می‌کند. هیچ endpoint خصوصی، سفارش، برداشت، انتقال یا تلگرام در این مسیر وجود ندارد.

## پیش‌نیاز
- Python 3.10 یا جدیدتر
- فقط وابستگی خارجی: `requests`
- SQLite از کتابخانه استاندارد Python استفاده می‌شود.

## نصب و اجرا
از پوشه `arbitrage_mvp`:

```bash
python -m venv .venv
# ویندوز: .venv\\Scripts\\activate
# لینوکس/مک: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run_scan.py
```

در ویندوز به‌جای `cp` می‌توان فایل `.env.example` را دستی به `.env` کپی کرد.

## واحد قیمت و تازگی داده
- طبق مستندات رسمی نوبیتکس، قیمت بازارهای ریالی در API بر حسب **ریال** است؛ بنابراین قیمت دفتر سفارش `IRT` برای مقایسه با قیمت تومان والکس باید بر ۱۰ تقسیم شود. مقدار پیش‌فرض `NOBITEX_IRT_PRICE_DIVISOR=10` همین تبدیل را انجام می‌دهد. منبع: https://github.com/nobitex/docs-api/blob/master/source/includes/_market_trade.md
- والکس بازارهای تومانی را با نمادهایی مانند `USDTTMN` منتشر می‌کند؛ `TMN` در اطلاعات دارایی والکس به تومان اشاره دارد. منبع: https://api-docs.wallex.ir/
- مستندات REST والکس برای `/v2/depth/all` زمان به‌روزرسانی هر دفتر سفارش را در ساختار پاسخ نمونه مشخص نمی‌کند. در نتیجه اسکنر فعلی زمان محلی دریافت را به‌جای زمان بازار نمی‌گذارد و فرصت فاقد timestamp معتبر را رد می‌کند.
- مستندات والکس کانال‌های زنده Socket.IO برای عمق خرید و فروش را معرفی می‌کند. مرحله بعدی برای استفاده از داده والکس باید دریافت زنده، نگهداری snapshot و کنترل اتصال/بازاتصال را جداگانه پیاده‌سازی و آزمایش کند؛ تا آن زمان هیچ سیگنال قابل‌قبولی با REST فعلی انتظار نمی‌رود.
- زمان سمت سرور نوبیتکس از `lastUpdate` خوانده می‌شود؛ اگر زمان وجود نداشته باشد یا قدیمی باشد، سیگنال رد می‌شود.

## تنظیمات حساس
- کارمزدها، لغزش و هزینه انتقال از متغیرهای محیطی خوانده می‌شوند؛ مقادیر نمونه، کارمزد واقعی صرافی نیستند.
- تا وقتی `FEES_CONFIRMED=true` و `TRANSFER_COST_CONFIRMED=true` نشده‌اند، فرصت‌ها واجد شرایط اعلام نمی‌شوند.
- هزینه انتقال فعلاً فقط یک فرض درصدی برای شبیه‌سازی است؛ تا زمانی که شبکه، کارمزد برداشت/واریز و امکان انتقال دارایی تأیید نشده‌اند، نتیجه سود قطعی نیست.
- نماد مشترک به‌تنهایی اثبات‌کننده یکسان بودن دارایی یا شبکه انتقال نیست.

## داده و تاریخچه
فایل `arbitrage_history.sqlite3` به‌صورت خودکار ساخته می‌شود. جدول‌های `scans` و `opportunities` زمان اسکن، شمار دفترها، تنظیمات، فرض‌ها، سود تخمینی و دلیل رد هر مسیر را نگه می‌دارند.

## امنیت و دامنه
در این MVP هیچ کلید API لازم نیست. هیچ کد سفارش‌گذاری/برداشت/انتقالی در این پوشه قرار ندارد. این پروژه ابزار آزمایش و ثبت فرضیه است، نه سامانه آماده معامله.
