# پروژه آربیتراژ والکس و نوبیتکس

این مخزن در حال بازآرایی است. مسیر پیشنهادی و مستقل برای توسعه و آزمایش آربیتراژ، پوشه **`arbitrage_mvp/`** است. این MVP فقط دفتر سفارش عمومی را با درخواست‌های GET می‌خواند، محاسبه شبیه‌سازی انجام می‌دهد و تاریخچه را در SQLite ثبت می‌کند.

## شروع سریع MVP

1. Python 3.10 یا جدیدتر نصب کنید.
2. وارد پوشه شوید: `cd arbitrage_mvp`
3. محیط مجازی بسازید و وابستگی را نصب کنید:

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

4. فایل `.env.example` را به `.env` کپی و تنظیمات را بررسی کنید.
5. اجرا: `python run_scan.py`

راهنمای کامل فارسی در [arbitrage_mvp/README_FA.md](arbitrage_mvp/README_FA.md) قرار دارد.

## مرزبندی اجزای مخزن

- **`arbitrage_mvp/`**: مسیر جدید و مستقل آربیتراژ؛ Python + requests + SQLite؛ فقط‌خواندنی و paper-only.
- **`arbitrage-ai-mvp/`**: پنل و مانیتور قدیمی‌تر؛ فعلاً مسیر اصلی توسعه MVP محلی نیست و تا زمان بازبینی جدا نگه داشته می‌شود.
- **`main.py` و `config.py` در ریشه**: کد قدیمی ربات قیمت بیت‌پین/DeepSeek؛ جزو مسیر اجرای آربیتراژ والکس/نوبیتکس نیست.

## قفل‌های ایمنی

- هیچ سفارش، معامله، برداشت یا انتقالی در MVP وجود ندارد.
- برای اسکن عمومی هیچ API Key خصوصی لازم نیست.
- کارمزدها، لغزش، تبدیل ریال/تومان و هزینه انتقال باید از تنظیمات خوانده و با داده واقعی تأیید شوند؛ مقادیر نمونه قطعی نیستند.
- تا وقتی زمان سمت سرور دفتر سفارش قابل اعتبارسنجی نباشد، سیگنال به‌عنوان داده تازه پذیرفته نمی‌شود.
- یکسان بودن نماد، اثبات‌کننده یکسان بودن دارایی یا شبکه انتقال نیست.
- خروجی حتی در صورت واجدشرایط بودن فقط یک نتیجه شبیه‌سازی است و مجوز معامله واقعی محسوب نمی‌شود.
- فایل‌های `.env`، پایگاه‌داده SQLite و محیط مجازی نباید در Git ثبت شوند.

## وضعیت پروژه

این مخزن پایه نمونه‌سازی و آزمون است، نه سامانه آماده معامله. ابتدا صحت داده، واحد قیمت، عمق دفتر سفارش، کارمزد و ذخیره‌سازی تاریخچه اعتبارسنجی می‌شود؛ داشبورد، تلگرام و استقرار در مراحل بعدی بررسی خواهند شد.
